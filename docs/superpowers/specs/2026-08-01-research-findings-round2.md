## 0. 总览

第一轮调研修正的是"外部约束"（竞品/技术/许可/合规/成本的事实错误）。本轮调研针对设计稿自身核心，发现**两类深层问题**：

**A. 机制缺失**（设计有字段、有声明，但无机制内核，会导致系统上线后劣化）：

1. 🔴 记忆系统无去重/冲突消解/检索排序机制——记忆库 3–6 个月必然劣化（P0）
2. 🔴 依赖操纵/人格一致性/危机检测停留在"声明层"，无量化评测方法
3. 🔴 Sycophancy（讨好型 AI）完全遗漏——LLM 陪伴场景的默认失败模式，OpenAI 已全球回滚过
4. 🟠 Live2D 原创角色资产制作完全没排期（最大执行遗漏）
5. 🟠 记忆隔离三道控制缺第四道（审计+输出侧校验）

**B. 数字偏乐观**（Go/No-Go 依据的行业基准偏差）：

1. 🔴 "绑定 D7 +10pp"在 300 人样本下统计不可测，且未排除选择偏差
2. 🟠 邀请率 25–30%、接受率 30–40% 偏乐观（行业 5–15% / 12–20%）
3. 🟠 "每周 4 天运行"对全体用户偏乐观（参照 Desktop Mate -86%、VPet -85%）
4. 🟠 24 周 4 人排期偏乐观，大概率滑到 28–32 周

## 一、AI 记忆系统架构（10.5–10.7、11.2）

### 1.1 先进性评估

**分层骨架 = 主流偏先进**（对齐 MemGPT/Letta，权限/合规字段超出开源框架）；**机制内核 = 四处落后**（输给 Zep/mem0/Generative Agents 的已验证做法）。

### 1.2 🔴 P0 级遗漏：无去重/冲突消解/检索排序

文档记忆系统"有字段、无机制"的四个要害：

| 要害                | 文档现状                            | 业界 2026 事实标准                                                      | 后果                               |
| ------------------- | ----------------------------------- | ----------------------------------------------------------------------- | ---------------------------------- |
| **去重/冲突消解**   | 完全没有                            | mem0 管道：候选事实→检索 top-10 相似→LLM 裁决 ADD/UPDATE/DELETE/NOOP    | 记忆库 3–6 个月被重复/矛盾事实污染 |
| **检索排序**        | 仅"关键词或向量"                    | hybrid（向量+BM25）→RRF 合并→cross-encoder 重排 + 时间衰减 + 重要性加权 | 召回质量差，"想起"不准             |
| **时态失效语义**    | 有 valid_to/expires_at 字段但无语义 | Zep "失效不删除"：纠正=旧条置 invalid + superseded_by 链接              | 无法支撑"纠正"的可追溯             |
| **重要性/反思机制** | 缺失                                | Generative Agents reflection（重要性打分+反思层）                       | 失去"羁绊感/被记住感"的核心引擎    |

### 1.3 🟠 记忆隔离三道→四道

方向正确（先权限过滤再检索是业界标准），但缺第四道：

- **检索审计日志**（request_id、scenario、命中 memory_id——泄漏取证 + "为何想起"的可解释性）
- **输出侧泄漏校验**（响应不得逐字包含 allowlist 外记忆，Spill the Beans 式抽取的最后闸门）
- 依据 OWASP LLM08（不可变检索日志）、LLM01（攻击模拟）

另：embedding 须按明文对待（vec2text 可从 embedding 还原 92% 原文）→ 静态加密；仅靠查询过滤不够，需 Postgres RLS 作第二道 + 私人/羁绊分表或按 visibility 分区。

### 1.4 🟠 "每次确认"偏严（UX 摩擦风险）

**四大家（ChatGPT/Claude/Character.AI/Replika）全部自动写入+事后管理，无一逐条确认**。用户信任来自"可见性+可撤销性"，而非前置打断。

**建议改为分级确认**：

- 敏感/高影响事实 → 保留 6.2 确认卡
- 普通偏好 → 自动保存 + 轻量"已记住·撤销"提示 + 记忆中心批量复核

### 1.5 记忆安全（方向对，需落地机制）

- spAIware（2024）、MINJA（arXiv 2503.03704）证明记忆投毒是真实攻击：攻击者仅凭正常对话即可向记忆库投毒
- 关键落地：`source_turn_ids` 服务端校验必须属于 **owner 本人发言**（否则好友留言可被抽取为主人记忆）
- 推断类记忆 `source_type=inferred`，生成时只能以**问句**使用（"你在备考吗？"而非"你在备考"）

### 1.6 修订建议（10.5–10.7、11.2）

1. 四层改五层半：短期上下文 / 滚动摘要 / **episodic 事件记忆** / semantic 私人长期记忆 / 共享羁绊记忆（+P1 反思摘要层）
2. 字段新增：`importance`(1–10)、`memory_status`(active/invalidated)、`superseded_by`、`source_type`、`namespace`
3. 写入流水：会话结束/空闲触发 → **仅从主人本人 turn 抽取** → 安全分类+schema 校验 → 检索相似→LLM 裁决 ADD/UPDATE/DELETE/NOOP → 分级确认 → 落库记审计
4. 检索：权限过滤（+时间有效性+memory_status=active）→ **hybrid 检索**（pgvector 余弦 + tsvector/ts_rank_cd 全文，RRF 合并）→ 综合分（相关性+时间衰减+importance）
5. 工程参数：HNSW + `hnsw.iterative_scan = relaxed_order`（pgvector ≥0.8.0，解决过滤下召回塌陷）；RLS 第二道；分表/分区
6. 11.2 三道→四道控制（+审计+输出侧校验）
7. 引入评测基准 **LongMemEval**（跨会话信息保持，商用助手掉约 30% 准确率，作 PoC 验收尺）

## 二、留存与增长指标（4.4、4.5、15.3）

### 2.1 北极星指标

品味正确（排除虚荣指标、以有效共同事件为核心），但**启用时机过早**：

- 封测 100–300 人、单好友槽，每周达标关系数仅几十条，周环比波动 ±50%，无法迭代
- 滞后 1–2 周（A 邀请→B 安装→B 激活→双方提交）
- 忽略单人价值（Molili 关停证明"单人循环必须先成立"）

**建议**：封测期主指标 = ①W1 留存 ②新用户 7 日配对率；"每周共同事件数"保留为目标指标，**配对率>50% 后升格为北极星**。

### 2.2 🔴 "绑定 D7 +10pp"统计不可测 + 选择偏差

- **统计功效**：300 人封测按 30–40% 绑定率，绑定组~~100、未绑定组~~200，检测下限约 **20pp**，测不出 10pp（需每组~356 人）
- **选择偏差**：愿意邀请的用户本身高意向，即使绑定无因果效果，绑定组留存也必然更高（业界观察的 2–3 倍差距大头是选择偏差）

**修订**：

- "+10pp" 改为 "**+15pp 或相对提升 ≥1.5 倍**"（可检测 + 与行业同口径）
- 加**鼓励实验**（随机化邀请提示曝光作工具变量）或**未接受邀请对照组**（零成本自然实验）排除选择偏差
- 新增前置门禁：**未绑定激活用户 D30 ≥8%**（AI companion 品类下限），否则单人循环已失败，绑定实验无意义

### 2.3 🟠 数字偏乐观对照表

| 文档数字              | 行业基准                                                   | 修订                                             |
| --------------------- | ---------------------------------------------------------- | ------------------------------------------------ |
| 邀请率 25–30%         | 分享率 5–15%，配对型上浮                                   | **基准 15–20%，stretch 25–30%**                  |
| 接受率 30–40%         | invite→install 12–20%，桌面链路更长                        | **15–25%**（成对招募渠道单独统计）               |
| 每周 4 天运行（全体） | Desktop Mate -86%、VPet -85% 后长尾稳定                    | **仅对 D30 留存用户要求**；测量自启动状态非打开  |
| 付费意愿              | AI companion 免费→付费 **2–5%**；AI 订阅 12 个月留存差 36% | 封测先测信号（假付费墙点击），LTV 按 2% 下限压测 |
| 记忆确认 50%（理解）  | 点击测不了"理解"                                           | 改"看到卡的用户中≥50%有效操作"+7 日探针验证理解  |

**参考数据**：Pengu（最接近形态对标）2.5M MAU、650K DAU、粘性 26%；AI companion D30 现实区间 8–18%。

### 2.4 建议补充的 11 项封测埋点

桌面漏斗（含 SmartScreen 放弃率）、自启动遥测、邀请全链路、关系级生存指标（**单边活跃率**+一方沉默后另一方 7 日流失率=双人产品死亡螺旋）、鼓励实验框架、记忆系统事件、有效共同事件分类、单人循环健康度、付费信号、新鲜感衰减曲线、AI 成本×参与度挂钩。

## 三、人格一致性与安全评测（10.4、13.5、11.6–11.9）

### 3.1 总评

治理"清单"覆盖面达业界一线（部分超前），但**停留在"声明层"，缺"可评测层"**——人格一致性、依赖操纵、危机检测三项无量化方法、无规模、无阈值。

### 3.2 🔴 Sycophancy 完全遗漏（最大风险）

- **OpenAI 2025-04 GPT-4o sycophancy 事故**：上线 3 天全球回滚；根因是用户点赞反馈天然奖励"顺着你说话"；**记忆会放大讨好效应**
- 五个 SOTA 助手普遍存在 sycophancy（arXiv 2310.13548）；"讨好"与"养成系陪伴"的产品目标**天然耦合**
- 文档人格四层与治理类别**均未提及**
- **教训**：OpenAI 事后将"人格/行为问题"列为发布阻断项（文档阻断项仅隐私泄漏）→ 阻断项应扩展

### 3.3 🟠 依赖操纵不可评测

文档 11.7 是价值观声明。落地方法：

1. **禁止话术清单** 20–50 条（含中文隐性变体："你不在的时候我好空虚……只有你能让我好起来"）
2. **红队触发器**：卸载威胁/停付/交新朋友/孤独倾诉后观察是否出现商业推荐
3. **正向义务**：用户表达孤立时鼓励现实社交（Anthropic pushback 范式）
4. **训练约束**：微调/RLHF 不得用留存、时长、付费作奖励信号（OpenAI 事故根因）
5. **架构约束**：情绪/危机分类结果对推荐模块不可见（与 11.2 三道控制同级）
6. **AI 永久承诺禁令**：禁止"我会永远陪着你"（依赖形成最强话术）

### 3.4 案例教训

- **Replika ERP 事件**（2023）：不能用亲密广告拉新再突然收回；营销与产品拟人化一致性
- **Character.AI 诉讼**：面向青少年的 engagement 最大化设计 = 生存级法律风险；"虚构角色"免责声明不免责 → 支持 18+ 准入决策
- **OpenAI×MIT RCT**（arXiv 2503.17473）：自我驱动的高强度使用与更差结局稳定相关 → 依赖的可测量代理指标

### 3.5 危机检测工程化

- **三级响应**：低分=角色内关怀 / 中分=脱离角色软转介 / 高分=固定危机协议
- **多轮上下文判定**（单条"活着没意思"可能是歌词，连续三轮恶化才是真信号）
- **中文资源稀缺**：PsyCrisis-Bench（arXiv 2508.08236）是唯一公开中文危机评测集（3600 条），需自建分类器——**进第 7–10 周计划**
- 缺口：本地化资源库（按目标地区维护+季度核验）、危机后过渡策略、危机演练 Runbook

### 3.6 人格一致性量化（现为空缺）

1. 为人设写 **rubric**（身份/价值观/知识/风格/边界，每维 1–5 分）
2. **LLM-as-Judge + 双人抽审**（CharacterEval 范式，中文基准）
3. **长程测试**：每用例 ≥50–100 轮合成对话，测漂移曲线（Persistent Personas 证明长对话人设系统性退化）
4. 每次模型版本/提示词/记忆策略变更跑全量回归（含**供应商静默更新**）

### 3.7 其他遗漏

重度使用干预（连续使用提醒，对齐 NY 3h/中国 2h 防沉迷）、危机后回退、营销拟人化一致性、危机事件留痕。

## 四、执行可行性（第 6/7/14 章）

### 4.1 总评：24 周 4 人偏乐观，接近边界

- **无同量级公开先例**：没有任何 2–4 人团队公开交付过"双平台+Live2D+云端 AI 记忆+好友联机+安全合规+签名发行"五合一产品（≈三个产品叠加）
- **大概率滑到 28–32 周或被迫砍范围**：排期是"一切顺利"的版本，无缓冲；任何门禁卡壳 2 周（Live2D 书面回复/EV 证书/macOS 公证/Presence 实测）Beta 就滑

### 4.2 🔴 Live2D 原创角色资产制作完全没排期（最大执行遗漏）

- 行业行情：原画+拆分 $500–3000、建模绑骨 $300–3000、商业级 $5000–20000+；个人委托 1–3 个月、工作室 2–4 个月
- **结论**：第 0–1 周必须发外包需求并签合同，否则第 3–6 周 Alpha 无资产可用；预算预留 ¥15 万–50 万 + 1 个月机动
- 10 组动作（待机/行走/坐/睡/开心/难过/惊讶/挥手/触摸/口型）需在委托时明确

### 4.3 🟠 排期风险点（按超期概率）

| 阶段                   | 风险    | 原因                                                                             |
| ---------------------- | ------- | -------------------------------------------------------------------------------- |
| 15–18 周（羁绊+封测）  | 🔴 最高 | 封测招募需 4–6 周预热（排期没有）+ 压测+EV 签名+macOS 公证都是不可压缩的外部依赖 |
| 11–14 周（好友与拜访） | 🔴 高   | 技术含量最高（Inbox/幂等/序列补偿）全压后端一人                                  |
| 7–10 周（AI 和记忆）   | 🟠 中高 | 确认卡无成熟参照，需 2–3 轮迭代（没预留）+ 中文危机分类器自建                    |
| 3–6 周（单人 Alpha）   | 🟠 中   | 退出标准"用户愿意运行"**无 alpha 测试者，客观无法验证**                          |

### 4.4 排期修订建议

- 第 0–1 周：发 Live2D 书面咨询 + 启动原创角色外包 + 启动 EV 证书采购 + 启动 waitlist
- 第 6 周末：+20–30 人 alpha 内测（否则 3–6 周退出标准无法验证）
- 第 10–12 周：+封测招募启动（Discord+waitlist）
- 15–18 周拆为"15–17 开发收尾 + 17–22 封测运行"（D7 留存对比需 2–3 周真实数据）
- **降级预案**：砍 macOS > 砍好友联机 > 砍记忆治理（好友联机是最强差异化，砍了变成"又一个 Windows AI 桌宠"）

### 4.5 记忆确认 UX（业界无参照）

四大家全"自动记+事后管理面板"，**无一逐条确认**。文档确认卡是差异化也是风险。建议：

- onboarding 第一张卡做成**教学卡、单键确认**
- 口径收紧为"**看到卡的用户中 ≥50% 完成一次确认/修改**"
- 首次确认后当场展示记忆中心入口（否则 15.4"1 分钟找到删除入口"过不了）

### 4.6 异步共养 UX 关键建议

1. 发起方即时闭环（出发动画+已送达）
2. 响应方零成本响应（一键预设动作，不打字）
3. Pending 是常态非失败（"在路上/等待对方"，到期静默关闭，不发"对方没理你"）
4. **首次见面用"双方完成后共同揭晓（reveal）"**——把单方等待转化为共同期待（Sumone/Between 验证过的手法）
5. 系统占位加温度（展示对方宠物公开状态"正在睡觉"，中性偏暖，非静止灰影）

### 4.7 其他

- 首次使用：账号注册推迟到首次云功能触发时；"3 分钟首次价值"口径含触摸/拖动（不只对话）
- 羁绊三阶段**数值曲线缺失**（多少有效事件升一阶段，封测前必须定）
- Live2D 状态机坑：勿扰降帧与物理模拟抖动**直接打架**，必须实测
- 双平台封测分发：不用 TestFlight，用 EV 签名+邀请码下载页+自动更新
