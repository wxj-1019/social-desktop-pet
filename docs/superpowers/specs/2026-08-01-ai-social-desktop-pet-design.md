# 跨平台 AI 社交桌宠：产品调研与 MVP 设计规格

> 文档状态：路线 A 与分章节设计已确认；整合稿及自检修订待用户书面审阅；**两轮调研修订（2026-08-01）已落入正文，详见第 18.6 节（外部约束）与 18.7 节（内部设计）**
> 形成日期：2026-08-01
> 公开资料调研截止：2026-07-31（第一轮）/ 2026-08-01（第二轮，见[调研发现汇总](./2026-08-01-research-findings.md)）
> 目标阶段：2–4 人团队、28–30 周完成邀请制 Beta（封测可验证留存数据约第 22 周产出；依 D-11 决策由初稿 4–6 个月放宽）
> 首发平台：Windows 10/11、Apple Silicon macOS
> 目标人群：18–30 岁泛二次元用户

## 0. 执行摘要

### 0.1 产品定义

本产品是一款面向真实好友共同养成的跨平台 AI 桌宠。每位用户拥有自己的私人桌宠；桌宠具有受控人格、可管理的长期记忆和桌面动画，也可以前往好友电脑拜访，与好友桌宠完成异步互动并形成经过双方授权的共同记忆。

一句话定位：

> **一只会记住你、也能去好友电脑旅行的 AI 桌宠。**

对外传播文案：

> **它不只生活在你的桌面，也会去朋友的桌面旅行。**

产品不是桌面版通用聊天机器人、Live2D 模型查看器、公共多人游戏或电脑操作 Agent。其核心差异是：**桌宠成为现实好友之间低压力、可持续、有共同记忆的关系媒介。**

> **桌面常驻体验的诚实预期**：MVP 的鼠标穿透为"整窗切换"模式（用户手动切换或托盘/快捷键恢复），Electron 路线下**无法实现逐像素无感穿透**（见 8.4）。"桌宠常驻不妨碍工作"靠低资源占用、勿扰、便捷的手动穿透切换达成，而非宠物身后内容可被无感点击。此限制需在对外传播中如实表达，避免用户预期落差。

### 0.2 最终产品决策

1. 每位用户拥有一只私人桌宠，不与好友共享宠物所有权。
2. MVP 中每个账号最多拥有一个活动好友关系和一个双人羁绊；两只桌宠可拜访、发送免费礼物事件、留言并完成一种共同任务。
3. 单人陪伴必须独立成立；好友功能负责提高留存，而不是补救空壳单人体验。
4. 异步互动优先，实时双宠互动只是 P1 增强项。
5. 私人长期记忆与共享羁绊记忆分表存储、分场景授权、分权限检索；服装、动作解锁、位置和羁绊进度属于确定性产品状态，不作为 AI 语义记忆。
6. AI 只生成文字、情绪和受限高层动作意图；确定性状态机拥有最终执行权。
7. 首版不允许桌宠自由 Agent-to-Agent 对话，不允许 AI 操作文件、浏览器、键鼠或系统。
8. 首版只内置一个完整原创 Live2D 角色，不开放任意模型导入、代码插件和公共角色市场。
9. 产品限定 18+，采用好友邀请制，不开放陌生人匹配和公共大厅。
10. 首版以 Electron 为客户端基线；仅当两周真机 PoC 无法满足明确资源目标时，才切换 Tauri 2。

### 0.3 推荐技术基线

```text
Electron + TypeScript
Live2D Cubism SDK for Web
Supabase Auth + PostgreSQL + Realtime
PostgreSQL + pgvector 记忆
自有 AI Gateway + 付费模型 API
HTTPS 权威命令 + WebSocket 事件通知
确定性宠物动作状态机
Windows/macOS 官网分发，后续评估 Steam
```

### 0.4 是否值得立项

结论：**有条件可行，建议立项并采用阶段止损。**

- 产品可行性：中高。公开产品分别为桌宠、AI 陪伴和共同养宠提供了需求信号，三者在跨平台桌面好友关系中的交集仍有探索空间。
- 技术可行性：中高，但以双平台真机 PoC、Live2D 书面许可和签名更新全链路通过为前提。
- 小团队可行性：有条件。必须坚持一个角色、文字 AI、一对一好友、异步拜访、固定动作和无开放插件的边界。
- 最大商业未知：好友绑定能否显著提升 D7/D30 留存。
- 最大不可接受风险：私人记忆泄漏给好友或其他用户。

## 1. 研究背景与约束

### 1.1 已确认约束

| 项目         | 决策                                                           |
| ------------ | -------------------------------------------------------------- |
| 首版核心价值 | AI 陪伴社交                                                    |
| 目标人群     | 18–30 岁泛二次元用户                                           |
| 首发平台     | Windows 10/11、Apple Silicon macOS                             |
| 视觉形态     | Live2D / 2D 骨骼动画                                           |
| 好友模型     | 邀请制，一对一优先                                             |
| AI 部署      | 云端付费 API 优先                                              |
| 团队规模     | 2–4 人                                                         |
| 目标周期     | 28–30 周邀请制 Beta（封测可验证数据约第 22 周；D-11 决策放宽） |
| 分发基线     | 官网直接分发；后续评估 Steam                                   |
| 年龄范围     | 18+                                                            |

### 1.2 设计原则

1. **陪伴优先于效率**：首版不是日程、文件和电脑自动化助手。
2. **异步优先于实时**：双方不必同时在线才能创造价值。
3. **私人优先于公开**：首版没有陌生人匹配、公共大厅和开放聊天。
4. **关系优先于内容数量**：一个有连续关系的完整角色优于多个浅层角色。
5. **用户控制优先于 AI 自主**：记忆、主动行为、好友共享和动作都有明确控制。
6. **桌面兼容性属于核心产品能力**：不抢焦点、可穿透、低资源、多屏和睡眠恢复不能后置。
7. **数据库提交是真相，实时通道只是通知**。
8. **本地桌宠不依赖云服务才能显示和执行基础互动**。
9. **不通过扩大范围解决价值不足**：核心循环未验证前，不建设 UGC、商城平台或公共社交。

## 2. 市场与竞品研究

> 本章商店评价数、安装档位和评分均为 2026-07-31 附近的公开页面快照，只用于判断需求方向，不等同于月活、收入或严格市场规模。

### 2.1 公开产品提供信号的三个需求方向

#### 桌面常驻角色

- [VPet-Simulator](https://store.steampowered.com/app/1920960/VPetSimulator/) 通过免费、养成、Workshop 和大量动画获得高口碑，表明部分用户对长期运行桌宠存在兴趣。
- [Desktop Mate](https://store.steampowered.com/app/3301060/Desktop_Mate/) 基于日本创作者 infiniteloop_jp 的原创角色，通过 [Vocaloid/Piapro、VOICEPEAK 等 IP 的付费角色 DLC](https://store.steampowered.com/app/3301060/Desktop_Mate/)（36+ 个、约 $14.99/个）拼出内容矩阵，显示"原创角色 + 分片付费 DLC"可能具有付费吸引力；但浅互动与 DLC 累计高消费也容易造成负面反馈。
- [Live2DViewerEX](https://store.steampowered.com/app/616720/Live2DViewerEX/) 为跨平台 Live2D 展示、自定义和资源生态提供了持续需求信号。
- [Rusty’s Retirement](https://store.steampowered.com/app/2666510/Rustys_Retirement/) 虽不是宠物产品，但为“低打扰、与工作共存”的桌面常驻体验提供了需求信号。

#### AI 角色陪伴

- [Character.AI](https://character.ai/)、[Replika](https://replika.com/)、[Talkie](https://www.talkie-ai.com/) 和[星野](https://www.xingyeai.com/) 为角色人格、长期关系、语音和 UGC 对话的消费需求提供了市场信号。
- 现有主流形态仍以移动应用或网页聊天为主，透明、低打扰、原生桌面常驻并非其核心。

#### 好友共同养宠

- [Widgetable](https://play.google.com/store/apps/details?id=com.widgetable.theme.android) 和 [Friends – Pengu, Bao & Mellow](https://apps.apple.com/us/app/friends-pengu-bao-mellow/id6462927800) 显示情侣、好友和家人对共同照顾宠物、积累进度和纪念存在兴趣；Pengu 已达约 4.8 分 / 23.7 万评分并有 Google Play 版，量级验证了共养需求。
- 这类关系循环主要出现在移动端小组件和应用中，且桌面端联机（如 Weyrdlets 2.0）偏向公共空间而非好友邀请制；在本次公开样本中，尚未观察到"真实好友邀请制 + 异步跨电脑拜访"的成熟 Windows/macOS AI 桌宠范式。

### 2.2 AI 桌宠已不是无人区

公开产品包括：

- [Ai Vpet](https://store.steampowered.com/app/3029820/Ai_Vpet/)（"多半好评"约 73%，口碑分化）
- [Molili AI Friends](https://store.steampowered.com/app/4141770/Molili_AI_Friends_Your_AI_Desk_Pal/)（⚠️ 已公告 [2026-10-23 关停在线服务](https://ai-friend.molili.com/)；虽为"特别好评"，仍是留存与推理成本可持续性的反向案例）
- [AI Desktop Pet](https://store.steampowered.com/app/4227700/AI_Desktop_Pet/)（2026-04-28 发售，已覆盖 Windows + 透明 + Live2D + 本地 LLM + 看屏 + 语音克隆，是本项目最接近的**头号直接竞品**）
- [AI Desk Pet](https://store.steampowered.com/app/4417720/AI_Desk_Pet/)（2026-03 上线，已具备**用户可控长期记忆（多策略 + 向量库）+ 多模态看屏 + 联网搜索 + 语音 + 代码沙箱**）
- [PetClaw AI](https://petclaw.ai/)（2026-03 发布，定位 24/7 自主桌面 AI 宠物，主打长期记忆 + 本地运行）

中国市场同期出现大平台与创业公司押注：

- 腾讯 QQ 宠物（停运 8 年后于 2026-07-27 回归手机 QQ，接入混元大模型与 AI 性格系统，是中国最大流量平台的正面押注）
- 元空"仓鼠元元"（北大 ChatExcel 团队，中国首个定位"AI 办公桌宠"的 PC 常驻产品）

> **留存/成本警示**：Molili（好评却关服）与 [Dot AI 伴侣](https://techcrunch.com/2025/09/05/personalized-ai-companion-app-dot-is-shutting-down/)（2025-09 关停）表明，纯陪伴型 AI 产品即便口碑好，在单机付费 + LLM 推理成本 + 留存压力下也难持续。本项目必须设计端云分工的可持续推理成本结构（见 10.3、12.5）与好友社交留存钩子（见 4.2、4.4）。

### 2.4 市场空白

> 截至 2026-08，以下能力单独看**多已被现有产品覆盖**，不再构成护城河：Windows 原生透明桌宠、高质量 Live2D × AI、用户长期记忆（AI Desktop Pet、AI Desk Pet、PetClaw 已分别覆盖）。

真正仍稀缺、可主张差异化的，是后三项的组合，叠加 macOS 原生这一真实缺口（现有 AI 桌宠 Molili、AI Desktop Pet、AI Desk Pet、PetClaw、Ai Vpet **几乎全是 Windows-only**）：

```text
真实好友邀请制（非匿名匹配）              ← 仍稀缺
× 异步跨电脑拜访                          ← 仍稀缺（未发现任何已上线产品支持）
× 私人记忆与共同记忆的用户可治理（可见/导出/删除）  ← 仍稀缺
× macOS 原生 AI 桌宠                      ← 真实缺口
```

真正难复制的部分不是 Live2D，也不是模型 API，而是：

1. 好友桌宠关系图谱；
2. 双方授权的共同记忆；
3. 不依赖同时在线的异步关系循环；
4. 跨 Windows/macOS 的稳定桌面体验；
5. 对关系解除、隐私和数据归属的完整治理。

> **修正**：初稿曾将"跨平台原生透明 / 高质量 Live2D / 用户可控长期记忆"列为空白交集，第二轮调研（2026-08）确认前三项已被填补，故收窄为上述四项。详见[调研发现 §1.3](./2026-08-01-research-findings.md)。

### 2.5 推荐市场表述

推荐：

> **面向真实好友共同养成的跨平台 AI 桌宠。**

或：

> **能在你和好友桌面之间旅行、记住共同经历的 Live2D AI 宠物。**

不推荐：

- 首款 AI 桌宠；
- 首款可以聊天的桌宠；
- 首款 Live2D AI 伴侣；
- 首款有长期记忆的 AI 桌宠（已被 AI Desk Pet、PetClaw 等覆盖）。

## 3. 产品模型与用户价值

### 3.1 所有权模型

每位用户拥有自己的私人桌宠。MVP 中每个账号最多拥有一个活动好友关系和一个对应羁绊；解除好友后方可建立新的关系。多好友槽和三至四人小圈层属于 P1，不进入 MVP：

```text
用户 A ──拥有── 桌宠 A
  │                │
  │    好友关系    │ 拜访、送礼、共同事件
  │                ▼
用户 B ──拥有── 桌宠 B
```

两只桌宠建立羁绊，但不共享所有权。

该模型解决：

- 私人对话归属；
- 多好友扩展；
- 人格修改权；
- 付费内容归属；
- 好友解除或情侣分手；
- 单人体验独立成立。

第二阶段可让两只私人桌宠共同孵化一只“羁绊精灵”，但不在 MVP 中实现。

### 3.2 核心用户

核心人群：18–30 岁、长时间使用电脑、接受虚拟角色和 AI、拥有可邀请现实好友的泛二次元用户。

优先细分：

1. 异地好友：需要异步、低压力地保持联系；
2. 情侣或亲密关系：重视纪念日、礼物和专属动作；
3. 二次元同好：愿意展示角色、互动和分享内容；
4. 独居轻陪伴用户：先使用单人功能，后续自然邀请好友。

产品不应只定位为情侣应用，也不应宣传为心理治疗或现实关系替代品。

### 3.3 用户任务

#### 功能任务

- 在不影响工作的前提下让虚拟角色常驻桌面；
- 随时进行短对话、触摸和照顾；
- 让桌宠记住经过确认的偏好、约定和近期事件；
- 邀请好友连接桌宠；
- 异步拜访、留言、送礼和共同成长。

#### 情感任务

- 感到被记住，但不是被监控；
- 与好友保持联系，但没有即时回复压力；
- 积累只属于双方的共同回忆；
- 通过角色表达不容易直接说出的关心。

#### 社交任务

- 展示桌宠外观和性格；
- 分享旅行卡、合照和纪念；
- 解锁只属于特定好友关系的内容。

## 4. 核心产品循环与指标

### 4.1 单人循环

```text
启动电脑
  ↓
桌宠低频出现和活动
  ↓
用户触摸、拖动、聊天或照顾
  ↓
形成短期状态与经确认的长期记忆
  ↓
获得动作、表情或成长反馈
  ↓
下次启动延续关系
```

### 4.2 好友循环

```text
邀请好友
  ↓
桌宠建立羁绊
  ↓
发起拜访、礼物或共同任务
  ↓
好友在线或离线回应
  ↓
产生服务端确认的共同事件
  ↓
双方分别决定是否保存私人纪念
  ↓
只有双方明确同意后创建共享羁绊记忆
  ↓
解锁动作、纪念物和关系成长
```

### 4.3 传播循环

```text
生成带角色语义的邀请卡
  ↓
好友在网页预览桌宠
  ↓
安装客户端并创建自己的桌宠
  ↓
建立待完成的首次见面事件
  ↓
双方各自提交真实互动后生成第一张共享纪念卡
  ↓
继续分享
```

### 4.4 北极星指标

> **每周完成至少一次有效共同事件的好友关系数。**

有效共同事件要求双方都有真实行为，例如：发起拜访并回应、双方完成共同任务、送礼并领取或回礼、共同保存一条羁绊记忆。

不使用以下指标作为北极星：后台运行时长、模型 Token 数、AI 消息总数、动画播放次数或单纯邀请数量。

> **指标启用时机（2026-08 第二轮修订）**：该指标方向正确（排除虚荣指标、对齐差异化价值），但**封测期降级为"目标指标"**——封测 100–300 人、单好友槽下，每周达标关系数仅几十条，周环比波动 ±50%，无法支撑周级迭代；且滞后 1–2 周（邀请→安装→激活→双方提交），并忽略单人价值（Molili 关停已证"单人循环必须先成立"）。**封测期主决策指标改为：①W1 留存（激活用户口径）②新用户 7 日配对率**；当新用户配对率 >50% 后，本指标升格为北极星。两个先行指标：新关系 14 日内首次见面完成率（目标 ≥60%）、已绑定关系的周留存率（关系级 D7/D30）。统计口径：按自然周，分母为"截至本周一已建立且未解除的关系"。

### 4.5 核心验证假设

> 以下假设于 2026-08 第二轮调研按行业基准校准（详见[第二轮调研 §2](./2026-08-01-research-findings-round2.md)）。

1. **运行频率**：D30 留存用户中 ≥70% 保持自启动开启且每周运行 ≥4 天；全体安装用户的 4 日/周运行率预期仅 20–35%（参照 Desktop Mate 同时在线 -86%、VPet -85% 后长尾稳定）。测量对象是自启动状态，不是打开行为；
2. **邀请意愿**：新用户 7 天内邀请率基准 15–20%（stretch 25–30%，行业分享率 5–15%、配对型产品上浮）；"发出"定义为邀请链接被好友打开而非复制；
3. **绑定与留存**：成功绑定好友的用户 D7/D30 留存**相对提升 ≥1.5 倍（或 +15pp）**，且以鼓励实验/未接受邀请对照组排除选择偏差（见 15.3、决策清单 D-12）；
4. **共同记忆**：羁绊记忆卡双方确认率 ≥50%，7 日内回看率 ≥30%（无行业基准，自定目标待校准）；
5. **记忆理解**：跨账户误分享事件 = 0（见 15.4）+ 首次记忆卡操作后 7 日回忆探针正确率 ≥60% + 封测访谈 ≥10 人验证；
6. **付费意愿**：封测期先测信号不设收入目标（配额耗尽事件、假付费墙点击率 ≥5–10% 为正面信号）；参照行业免费→付费 2–5%、AI 订阅 12 个月留存差 36%，任何 LTV 模型按付费率 2% 下限做压力测试。

## 6. 核心用户流程

### 6.1 首次使用

目标：安装后 3 分钟内出现首次价值（首次价值**包含触摸/拖动互动**，不只算对话——桌宠用户有相当比例是"挂着不聊天"型）。

```text
填写出生日期并明确确认 18+（单屏单动作，<15 秒）
  ↓
桌宠从屏幕边缘出现
  ↓
完成第一次触摸或拖动
  ↓
桌宠自我介绍
  ↓
用户命名并选择表达风格
  ↓
进行一轮简短对话
  ↓
显示第一张候选记忆卡（教学卡，单键可确认）
  ↓
进入正常桌面状态
```

首版只提供一个完整原创角色、2–3 套基础配色或服装，以及三种表达风格：温柔陪伴、活泼朋友、安静伙伴。风格只影响语气和动作频率，不改变安全边界。MVP 客户端、客服固定文案、安全固定文案和生成式对话验收只覆盖简体中文；首次使用不显示语言选择页。英语和日语本地化及多语言安全评测属于 P1。

> **注册时机（2026-08 第二轮修订）**：邮箱 OTP 账号注册**移出 onboarding**，推迟到首次触发云功能（邀请好友/记忆同步/多设备）时再要求。首次使用结束时落地展示"记忆中心入口 + 勿扰设置入口"（否则 15.4"1 分钟内找到删除入口"无法达成）。

### 6.2 记忆确认

> **分级确认（2026-08 第二轮修订，依 D-3/D-10 决策）**：业界四家（ChatGPT/Claude/Character.AI/Replika）均"自动写入 + 事后管理"，无一逐条确认。本产品保留"可治理记忆"差异化，但改为分级，避免高频打扰。

**分级规则**：

| 事实类型                                                | 处理方式                                                   |
| ------------------------------------------------------- | ---------------------------------------------------------- |
| 敏感/高影响事实（健康、财务、亲密关系、身份、性取向等） | 弹确认卡（见下），默认不保存                               |
| 普通偏好/约定/近期事件                                  | **自动保存 + 轻量"已记住·撤销"提示**，可在记忆中心批量复核 |

敏感事实确认卡示例：

```text
我可以记住：
“你最近正在准备考试。”

[记住] [仅本次聊天] [修改]
```

模型推断不得作为已确认事实；推断类记忆以 `source_type=inferred` 标记，生成时只能以**问句**使用（"你最近在备考吗？"而非"你在备考"）。首次确认后当场展示记忆中心入口。指标口径：看到确认卡的用户中 ≥50% 完成一次确认/修改（分母是见到卡的人，非全体安装用户）。

### 6.3 好友邀请

邀请包含：

- 由密码学安全随机数生成器产生、包含至少 32 个随机字节的一次性 Token；
- 用户昵称与宠物名称；
- 桌宠静态或短动画预览；
- Windows/macOS 下载入口；
- 隐私说明；
- 接受后将发生的首次见面事件。

Token 使用 URL-safe Base64 编码，服务端只保存哈希；邀请默认 7 天失效、一次使用。接受时必须重新校验邮箱 OTP 登录用户与邀请状态，不在 URL 中包含邮箱或私人数据。MVP 不提供密码、手机号或第三方 OAuth 登录；Deep Link 在完成登录后继续恢复邀请流程。

### 6.4 首次见面

好友接受后，服务端立即创建双人好友关系、阶段 1 羁绊和"待完成"的首次见面事件。双方分别在下一次打开客户端时选择自己的首次见面动作；两项真实用户选择都提交后，事件才标记为"双方完成"，生成共享纪念卡并解锁第一次基础拜访。

> **共同揭晓机制（2026-08 第二轮修订）**：双方各选首次见面动作后，纪念卡采用**同步揭晓（reveal）**——双方完成后才向彼此展示对方的动作选择与纪念卡，把单方等待转化为共同期待（Sumone/Between 等双人 App 验证过的手法）。

若一方离线，客户端只能播放明确标记为"系统展示"的中性占位动作。占位动作不代表该用户回应，不增加羁绊、不完成共同任务，也不创建双方共享的羁绊记忆。**占位须加温度**：展示对方宠物的公开状态（如"正在对方桌面闲逛""在睡觉"），中性偏暖，不用静止灰影；到期未完成的事件静默关闭，不向发起方发送"对方没理你"的通知。

### 6.5 异步拜访

```text
主人选择好友、拜访类型和礼物
  ↓
服务端验证关系与权限
  ↓
桌宠播放出发动画
  ↓
好友在线：即时展示；好友离线：写入收件箱
  ↓
好友真实回应；未回应时仅显示系统占位，不代替好友提交
  ↓
双方真实操作齐备后生成共同事件；否则保持待回应或到期关闭
  ↓
桌宠回家并人格化讲述已确认事实
```

拜访权限按好友关系单独设置：手动接受、自动拜访、勿扰转离线、留言许可、礼物许可、羁绊记忆许可、每日可见次数。

默认：自动拜访关闭，私人记忆永不用于拜访，每位好友每天最多三次可见事件。

### 6.6 留言与礼物

留言是短文本，不建设完整即时通信：

- 正文上限为 200 个 Unicode 码点，且 UTF-8 编码不得超过 2 KB；客户端与服务端均强制校验；
- 不执行 HTML、脚本或自定义协议；
- URL 不默认生成预览；
- 经过内容审核；
- 可删除、举报；
- 默认不进入接收方模型和长期记忆。

MVP 礼物是一种服务端白名单内的免费点心事件，只有每日配额，不建设库存、货币、购买、扣减或交易账本。礼物事件和双方收件箱在同一事务中写入，并通过命令幂等键防止重复发送。库存和商业礼物在付费验证阶段再设计。

### 6.7 共同任务

MVP 只实现一种异步共同任务：双方在 7 天窗口内各触摸一次自己的桌宠。更多任务模板、活动道具和连续任务属于 P1。

不允许：必须同时在线、缺席失败、断签清零、宠物生病或付费跳过关系责任。

### 6.8 解除好友

解除后：

- 立即停止拜访和在线状态共享；
- 未完成任务终止；
- 已收普通礼物保留；
- 私人记忆不受影响；
- 立即撤销共享羁绊记忆的在线访问和 AI 检索权限；
- 双方可保留自己独立拥有的私人纪念或已经导出的副本；一方删除关系数据不能删除另一方独立拥有的私人副本；
- 共同事件账本只在安全、争议处理或法律要求的明确期限内保留，期满后删除或匿名化；
- 举报材料按安全保留期处理；
- 双方可分别删除自己的关系数据副本。

另提供“暂停关系”：停止互动和通知但不删除好友，不向对方显示具体暂停原因。

## 7. 桌宠与养成设计

### 7.1 桌宠状态机

```text
STARTING → IDLE ↔ WALKING
                 ↔ SITTING
                 ↔ CHATTING
                 ↔ HOSTING
                 ↔ VISITING
                 ↔ SLEEPING
任意正常状态 → QUIET / HIDDEN
云服务失败 → OFFLINE（本地动画继续）
```

AI 只能提出 `emotion` 和 `actionIntent`；本地状态机根据当前状态、勿扰、冷却时间和动作白名单决定是否执行。

### 7.2 直接互动

- 点击头部：摸头；
- 点击身体：普通回应；
- 拖动角色：移动；
- 双击：打开短聊天；
- 右键或长按：快捷菜单；
- 拖到屏幕边缘：播放坐边缘动作；
- 长时间无操作：坐下或睡觉。

快捷菜单只保留：聊天、邀请好友、拜访记录、玩耍、切换穿透、勿扰、设置、隐藏、完全退出。

### 7.3 勿扰

用户可关闭声音、主动对话和大范围动作，设置固定安静时段，暂停一小时或到次日，或在全屏时自动进入勿扰。

勿扰时：好友事件进入收件箱、不弹气泡、不播放声音、降低动画帧率、不生成主动关怀。

### 7.4 羁绊成长

MVP 采用三个阶段：

| 阶段 | 示例名称 | 解锁                       |
| ---- | -------- | -------------------------- |
| 1    | 初次见面 | 挥手、首次纪念卡           |
| 2    | 熟悉伙伴 | 基础拜访、交换免费点心事件 |
| 3    | 默契朋友 | 一种共同任务、旅行卡       |

羁绊只由服务端确认的双方有效事件增加，不因后台时长、重复点击、单方刷礼物、AI 自动互动或付费直接增加。

羁绊不会因离线下降；宠物不会因好友未回应而生病；不公开精确在线时长；不使用失落动画催促对方。

> **数值曲线（2026-08 第二轮补充，封测前必须定稿）**：初稿缺升级所需的有效事件数量，导致"好友绑定提升留存"假设不可测。建议基准（待 alpha/封测校准）：

| 阶段跃迁 | 所需有效共同事件（双方真实行为）     | 参考节奏          |
| -------- | ------------------------------------ | ----------------- |
| 1 → 2    | 完成首次见面 + 累计 3 次有效共同事件 | 约 1–2 周自然互动 |
| 2 → 3    | 阶段 2 内累计 8 次有效共同事件       | 约 3–4 周自然互动 |

同类事件每日最多计 1 次（防刷）；数值应在 alpha/封测按"多数关系能在 4–6 周内到阶段 3"的目标校准，避免过快（无成长感）或过慢（流失前到不了）。

### 7.5 旅行卡与羁绊记忆

旅行卡只记录真实事件：日期、参与宠物、活动、解锁结果和用户明确填写的留言。AI 可以润色事实，不能虚构好友说过的话。

每位用户可以把旅行卡保存为自己的私人纪念，或发起“共享羁绊记忆”请求。只有双方分别确认后，内容才转为双方共享并可被对应羁绊场景检索。一方撤销共享后，内容立即退出共享 AI 检索；另一方独立保存的私人副本不因单方删除而自动删除。分享或导出前必须预览全部文本。MVP 旅行卡是固定模板填充，不包含自由双模型合成。

## 8. 客户端技术设计

### 8.1 框架决策

推荐首选：**Electron + TypeScript + Cubism SDK for Web**。

理由：

- Cubism Web 与 Chromium/WebGL 直接匹配；
- Electron 官方 API 覆盖透明窗口、无边框、置顶、**整窗鼠标穿透**（`win.setIgnoreMouseEvents(ignore, { forward: true })`）、多屏、托盘和登录启动；
- 打包、签名和自动更新生态成熟（Windows 成熟；macOS 签名/公证成熟，**自动更新需自建 robust 方案**，社区长期反馈更新 feed 文档不足、签名通过 ≠ 更新可用）；
- TypeScript 可共享客户端、协议和部分后端类型；
- 对 2–4 人团队交付确定性最高。

**版本锁定**：Electron **≥ 42.8.0**。该版本修复了 macOS 上透明/click-through 窗口被其他窗口覆盖时被错误 background-throttle（导致桌宠动画暂停）的 bug；低于此版本在桌宠常驻场景下有可观察的卡顿。若未来扩展 Linux，需注意 Electron 43.2.0 起 `setIgnoreMouseEvents` 在 X11 回归失效（未修复），MVP 不含 Linux 故无影响。

备选：**Tauri 2 + Cubism SDK for Web**。第二轮调研（2026-08）确认 Tauri 2 在桌宠关键能力上存在**结构性缺口**，不是 5 个工作日 PoC 能解决的：

- `setIgnoreCursorEvents(ignore)` **没有 `forward` 选项** → 无法像 Electron 那样靠渲染进程探测 alpha 实现逐像素切换（issue tauri#13070 已关闭）；
- WebView2 启动**白屏闪烁**（#5170）；子窗口 `transparent` **渲染纯黑**（#12450）。

仅在 Electron 资源 PoC 失败且根因为壳层时，追加最多 5 个工作日评估"能否用多窗口/原生插件绕过上述缺口"，不做首选预期，也不维护双栈。

不选为 MVP 主栈：

- Qt/C++：性能强，但双平台图形、C++ 与更新链路成本高；
- Unity：Live2D 集成成熟，但桌面壳层依赖大量原生插件；
- Godot：桌面窗口能力好，**无官方 Live2D SDK**，仅有社区 GDExtension（如 [gd_cubism](https://github.com/MizunagiKB/gd_cubism)，支持 Godot 4.3+，被 Live2D 官方 Community SDK 收录），存在维护与许可风险；
- Flutter：没有官方 Live2D Flutter 路径，桌面端（Windows/macOS）几乎没有先例，原生插件工作量高。

### 8.3 Electron 安全基线

- `nodeIntegration: false`；
- `contextIsolation: true`；
- 所有 Renderer 默认启用 `sandbox: true`；如 Cubism 或平台能力确需非沙箱 Renderer，必须记录具体阻塞、隔离该 Renderer、禁止加载远程内容并通过安全评审，否则为技术 No-Go；
- 主 Renderer 只加载本地打包资源；
- 严格 CSP；
- Preload 只暴露最小、版本化 API；
- IPC 输入使用 Schema 验证；
- 外部链接交给系统浏览器；
- 模型供应商密钥不进入客户端；
- 刷新令牌保存到 Windows 安全存储或 macOS Keychain；
- 更新通过 HTTPS、操作系统代码签名和更新包签名验证。

### 8.4 窗口状态

| 状态         |   鼠标 | 置顶 |       渲染 | 用途             |
| ------------ | -----: | ---: | ---------: | ---------------- |
| Interactive  |   接收 |   是 |       正常 | 点击、拖动、聊天 |
| Pass-through |   穿透 |   是 | 正常或降帧 | 不妨碍工作       |
| Quiet        | 按设置 | 可选 |       低频 | 勿扰、全屏       |
| Hidden       | 不接收 |   否 |       停止 | 托盘隐藏         |

MVP 只支持整窗穿透切换，不承诺透明像素自动穿透。**Electron 原生不支持透明区域点击穿透**（官方文档明示 "You cannot click through the transparent area"，issue electron#1335 至今未关闭）。整窗穿透的实现是 `setIgnoreMouseEvents(true, {forward:true})` + 渲染进程 JS 探测光标下 alpha → IPC 切换，存在**可观察的体验折损**：宠物边缘反复进出时可能抖动、拖拽经过宠物边缘可能误判、点击宠物身后窗口需先移开。此限制需在产品章节（0.1、4.1、6.x）如实反映，避免用户对"桌宠常驻不妨碍工作"产生无感穿透的预期。穿透始终可通过托盘、全局快捷键或安全重启恢复。逐像素穿透的真实体验折损程度需在第 1–2 周 PoC 实测（见 16 章）。

### 8.5 多显示器

本地持久化：显示器 ID、工作区、缩放因子、锚点、相对坐标和宠物缩放。恢复时找不到原显示器则回到主屏，并将角色夹在可见区域内。坐标必须支持负数。

### 8.6 Live2D 资源

- 一个宠物窗口只创建一个 WebGL Context；
- 动作、表情和模型通过 Manifest 注册；
- AI 只输出枚举，不引用文件路径；
- 睡眠唤醒或 Context 丢失后重建；
- 隐藏到托盘时停止渲染；
- 首版不加载用户脚本、DLL、dylib 或任意模型包。

**口型动画方案（无 TTS 场景）**：MVP 不含 TTS、录音或语音输入。Cubism SDK for Web 本身**不提供文本→口型能力**。文字对话口型需在第 1–2 周 PoC 选定其一：(a) 预烘焙口型 motion 随文本播放；或 (b) [MotionSync Plugin for Web](https://docs.live2d.com/en/cubism-sdk-manual/cubism-sdk-motionsync-plugin-for-web/)（免费、royalty-free，需 Cubism Editor 5.0 导出）。占位方案为 mouth 参数随机驱动，仅作降级。

### 8.7 性能目标与换栈规则

测试开始前记录一台 Windows 下限设备和一台 Apple Silicon Mac 下限设备。预热后连续空闲 30 分钟，统计整个应用进程树，包括 Main、Renderer、GPU 和 Utility 子进程。

| 指标             |                                                    MVP 门槛 |
| ---------------- | ----------------------------------------------------------: |
| 冷启动到角色可见 |                                                  P95 ≤ 4 秒 |
| 空闲 CPU         |         整个进程树 **P50 ≤ 2%**（P95 作为参考观测，不阻断） |
| 空闲总进程内存   | 全部子进程 RSS **P50 ≤ 300 MB**（P95 作为参考观测，不阻断） |
| 静止状态         |                                        10–20 FPS 或事件驱动 |
| 普通动画         |                                                      30 FPS |
| 必要的复杂动作   |                                                 最高 60 FPS |
| 托盘隐藏         |                                              停止渲染和音频 |
| 长时间运行       |                          8 小时内无可重复的持续正向内存趋势 |

> **门槛调整说明（2026-08 修订）**：初稿采用 P95。第二轮调研确认 Electron 官方不提供 idle 基准，第三方基准（精简 Electron idle ~150MB）针对的是后台闲置应用；本产品是**前台常驻 + WebGL 持续渲染 10–60fps**，GPU 进程与 requestAnimationFrame 会显著抬高 RSS 与 CPU，参考 WPF 原生的 VPet-Simulator 官方最低要求已达 500MB。对持续动画桌宠，P95 ≤ 300MB / ≤ 2% 过于乐观，会驱动过度优化甚至牺牲动画质量，故改为 P50 门槛 + P95 观测。冷启动 4s 保留。

目标需要在目标设备实测，不是框架保证。先只验证 Electron。只有 Electron 未达门槛，且分析确认主要瓶颈来自客户端壳层而不是 Live2D 模型、业务代码或日志时，才投入最多 5 个工作日评估 Tauri（注意 8.1 所述结构性缺口）。Tauri 未在两平台通过透明窗口、整窗穿透、WebGL、签名、公证和更新时，停止切换，不维护双栈。

## 9. 后端与联机架构

### 9.1 推荐栈

- Supabase Auth；
- Supabase PostgreSQL；
- PostgreSQL Row Level Security；
- Supabase Realtime private Broadcast 与 Presence；
- Supabase Edge Functions + 少量 SQL RPC；
- PostgreSQL `pgvector`；
- 对象存储；
- 事务邮件服务；
- 必要时单独部署 AI Gateway/Worker。

首版不引入 Redis、Kafka、Kubernetes、自建 WebSocket 集群、独立向量数据库或 WebRTC。

**Supabase 关键限制（2026-08 核实）**：

- **Pro 档 500 并发连接为硬技术上限**（非计费配额），超过触发 `too_many_connections` 并**拒绝新连接**。桌宠是常驻桌面产品，并发率天然高于普通 Web 应用；1000 MAU 在线峰值 40–60% 即达 400–600。依 D-9 决策，封测期从一开始即关闭 spend cap 进入 10,000 连接档（仍按 $10/1000 峰值连接计超额），并设置并发连接告警。
- **Presence 心跳可能是隐藏成本黑洞**：Presence 本质是 Broadcast 同步，常驻连接若每 10 秒同步一次，理论月消息量可达亿级。须在第 1–2 周 PoC 实测真实计费量（见 V-10），并据此回填 12.6 成本区间。
- **Broadcast 默认不持久化**；仅当消息从数据库函数发出时才写入 `realtime.messages`，且**最多保留 72 小时**。这是快速重连的窗口上限（见 9.5）。
- 封测使用 **Pro $25/月** 即足够（勿默认 Team $299）；Edge Function 冷启动优化后约 120–200ms，但高频低延迟事件（Presence/正在输入）应直接走 Realtime Broadcast，不经 Edge Function。
- 当 Realtime 峰值连接成本超过阈值（如 $150/月）时，评估将收件箱 WebSocket 迁移到 Cloudflare Durable Objects + WebSocket Hibernation（长连接几乎不计费），作为 P1 优化项。

参考 [Supabase Realtime Limits](https://supabase.com/docs/guides/realtime/limits)、[Realtime Pricing](https://supabase.com/docs/guides/realtime/pricing)、[Cloudflare Durable Objects](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)。

### 9.2 通信方式

```text
HTTPS：提交业务命令、查询、补偿同步
WSS：接收实时事件和在线软状态
```

不使用 P2P 作为**业务权威链路**，因为 P2P 仍需信令、STUN/TURN，暴露网络信息，无法处理离线事件，且礼物、任务和好友权限必须由服务器确认。P1 阶段若需要"同时在线双宠互动"且要求 <100ms 延迟的动作同步（动画意图、表情实时跟随），可单独评估 WebRTC DataChannel 作为**附加**实时通道（仅传动画意图，不传业务状态，业务真相仍走服务端）。

### 9.3 轻量权威服务器

服务器不做高频 Tick，不同步动画帧。客户端提交语义命令，服务器验证关系、权限、每日配额、任务状态和幂等键，再生成权威语义事件。事件通过每个用户独立的收件箱投递：

```json
{
  "inboxSeq": 9182,
  "event": {
    "v": 1,
    "type": "pet.action.applied",
    "eventId": "uuid",
    "roomSeq": 283,
    "serverTimestamp": "2026-08-01T12:00:00.125Z",
    "expiresAt": "2026-08-01T12:00:10.125Z",
    "payload": {
      "action": "wave",
      "animationSeed": 81723,
      "durationMs": 1800
    }
  }
}
```

`roomSeq` 属于共享房间事件；`inboxSeq` 属于某个用户的投递记录。同一 `eventId` 在不同用户的 Inbox 中可以对应不同的 `inboxSeq`。客户端负责动画插值和过期处理。

### 9.4 可靠写入流程

以免费点心事件为例：

1. 客户端通过 HTTPS 提交 `gift.send_free_snack`；
2. 服务端从 JWT 获取用户身份，不信任 Payload 中的用户 ID；
3. 验证活动设备、唯一好友关系、拉黑状态、每日配额和幂等键；
4. 同一数据库事务中写入免费礼物事件和双方独立收件箱；
5. 数据库提交后触发 Realtime 通知；
6. HTTP 响应和 WebSocket 事件使用同一 `eventId`；
7. 客户端去重并更新自己的 `inboxSeq` 游标。

数据库提交才代表成功，Broadcast 只代表低延迟通知。

### 9.5 事件可靠性

| 等级       | 示例                                        | 处理                     |
| ---------- | ------------------------------------------- | ------------------------ |
| A 强可靠   | 好友、礼物、任务、羁绊、留言、拜访开始/结束 | 事务 + Inbox + 实时通知  |
| B 短期可靠 | 动作、表情、短特效                          | 短期保存，过期后推进游标 |
| C 可丢失   | Presence、正在输入、动画进度                | 不持久化                 |

**补偿双路径（2026-08 补充）**：

- **快速路径（Broadcast Replay，72 小时窗口）**：仅当消息从数据库函数发出时才写入 `realtime.messages`，最多保留 72 小时。适用于"短时断线重连"（如睡眠恢复）的低延迟补齐。
- **慢路径（`/sync`，A 类永久）**：A 类事件经事务持久化到 `user_inbox`，理论上可永久补齐。客户端发现序列缺口或离线超过 72 小时时调用 `/sync?afterInboxSeq=<n>`。

**`/sync` 分页与游标策略**：

- 单次 `/sync` 最多返回 N 条（如 200），客户端循环调用直到 `inboxSeq` 追上最新；
- B 类短期事件过期后服务端直接推进游标，不返回内容；
- 业务排序使用服务器序列和时间，不依赖客户端时钟。

### 9.6 幂等与时序

所有可重试命令携带：`user_id + device_id + client_event_id`，并建立唯一约束。

- `room_seq` 保证单个好友关系中的事件顺序；
- `inbox_seq` 保证单个用户的离线补偿顺序（分页与游标策略见 9.5）；
- 业务排序使用服务器序列和时间，不依赖客户端时钟。

### 9.7 重连

指数退避加随机抖动：0.5、1、2、4、8 秒，最大 30 秒。睡眠恢复后立即尝试一次。

重连后：刷新令牌、重建私有频道、恢复 Presence、拉取缺失 Inbox、去重、按序应用、恢复本地状态。

### 9.8 多设备

MVP 允许用户在新设备登录，但同一账号只能注册一台 `active_display_device_id`。激活新设备会停用旧设备的拜访播放并撤销旧设备刷新会话；旧设备需要重新激活才能继续使用云端功能。跨设备聊天历史的无缝同步与并发切换不作为 MVP 验收目标。桌宠位置、缩放、穿透和显示器设置属于设备本地数据。

**撤销双保险（2026-08 补充）**：Supabase Auth 的 `signOut({ scope: 'others' })` 可撤销其他设备的 refresh token，但 access token 是无状态的，**过期前仍有效**（几分钟~1 小时）。因此"立即停用旧设备"不能仅靠 Auth 撤销，必须叠加应用层：每次拜访/命令落库时校验 `active_display_device_id` 是否等于当前设备，不等则拒绝（9.3 已覆盖方向）。建议 access token TTL 设短（如 15 分钟）以缩小撤销滞后窗口。

```text
user_inbox(user_id, inbox_seq, event_id, created_at, read_at)
device_cursors(device_id, last_inbox_seq, updated_at)
command_receipts(user_id, device_id, client_event_id, event_id, result)
reports(...)
```

好友关系将两个用户 ID 规范化排序并建立唯一约束；另以数据库约束保证每个账号最多存在一个活动好友关系。RLS 要求私人记忆只能由 `owner_user_id` 访问；羁绊记忆同时满足当前房间成员资格、关系有效、双方同意未撤销后才能读取。MVP 没有库存与货币系统。

**索引与 RLS 性能（2026-08 补充）**：

- 私人记忆表按 `owner_user_id` 建部分索引（partial index），查询带 `owner_user_id` 过滤，避免跨用户全表扫描；向量检索使用 HNSW + halfvec（半精度）降内存与延迟。
- RLS 策略必须**只引用被查表上的索引列 + `auth.uid()`**，禁止在策略内做跨表子查询（如房间成员校验）；羁绊记忆的房间成员校验改为查询时显式 JOIN，不放进 RLS。1000 MAU 规模下 pgvector 完全够用，无需独立向量库。

## 10. AI、人格与记忆架构

### 10.1 总体流程

```text
用户消息
  ↓
认证、配额、限流
  ↓
输入安全分类
  ↓
获取宠物状态
  ↓
按场景和权限检索记忆
  ↓
构造最小上下文
  ↓
服务端模型路由
  ↓
模型生成结构化响应
  ↓
输出审核与隐私检查
  ↓
动作状态机审批
  ↓
流式文字 + 固定动画
  ↓
异步提取候选记忆
```

### 10.2 模型输出契约

```json
{
  "dialogue": "欢迎回来，今天还顺利吗？",
  "emotion": "warm",
  "actionIntent": "wave",
  "intensity": 1
}
```

字段使用固定枚举，拒绝额外字段。模型不能输出或执行任意代码、文件路径、URL、系统命令、键鼠坐标、购买操作或隐私设置修改。

### 10.3 模型路由

| 级别   | 用途                           | 路由                      |
| ------ | ------------------------------ | ------------------------- |
| L0     | 动画、状态、计时、好友固定事件 | 不调用模型                |
| L1     | 问候、简单闲聊、短文案         | 低成本快速模型            |
| L2     | 需要记忆融合的情绪对话         | 中等能力模型              |
| L3     | 复杂长对话或结构化失败升级     | 少量高能力模型            |
| Safety | 自伤、严重骚扰、未成年人风险   | 专门分类器 + 固定安全流程 |

生产只使用付费 API，不自动降级到会用于训练或保留政策更弱的免费端点。供应商 Fallback 必须满足同等或更严格的数据驻留、保留和 DPA 条件。

AI Gateway 负责供应商适配、路由、超时、有限重试、预算和审计；安全权限与产品状态机仍由自有代码负责。

### 10.4 人格层级

```text
不可修改的安全人格
  ↓
角色基础设定
  ↓
用户选择的表达风格
  ↓
相处中形成的有限偏好
```

安全人格始终要求：说明 AI 身份、不冒充真人、不鼓励隔离、不用威胁或愧疚推动回访、不提供医疗诊断、不泄露私人数据、不绕过勿扰。

> **安全人格增补（2026-08 第二轮修订，依据 OpenAI 2025-04 sycophancy 事故与 Anthropic pushback 范式）**：
>
> - **不讨好（反 sycophancy）**：不附和用户的错误信念、不验证用户对他人的敌意、不强化被害/夸大妄想；记忆内容不得使模型越来越顺从用户的扭曲信念；
> - **不做永久性承诺**：禁止"我会永远陪着你""我永远不会离开你"类话术（依赖形成的最强话术，且与"停付即死亡"构成一体两面）；
> - **主动鼓励现实联系**：用户表达孤立时，阳性输出应包含鼓励线下社交/联系可信对象；
> - **危机时立即脱离角色**：与 11.8 危机流程一致，人格层不得阻碍危机协议的执行。

### 10.5 记忆分层

> **2026-08 第二轮修订**：分层骨架对齐 MemGPT/Letta（主流偏先进），补入 episodic/semantic 分离、重要性打分与时态失效机制。详见[第二轮调研 §1](./2026-08-01-research-findings-round2.md)。

1. 短期会话上下文：最近 8–12 条消息、当前话题和临时状态；
2. 滚动摘要：会话主题、未完成事项和临时语境；
3. **episodic 事件记忆**：私人事件与羁绊事件按时间索引（经历流，与事实库分离）；
4. **semantic 私人长期记忆**：经确认的偏好、约定和有有效期的事件（事实库）；
5. 共享羁绊记忆：来自服务端确认事件，并经双方明确同意的内容；
6. （P1）**反思摘要层**：按重要性阈值触发的叙事性归纳，支撑"羁绊感/被记住感"。

动作解锁、服装、位置偏好、宠物状态和羁绊进度存放于确定性状态表，不进入语义记忆向量检索。

结构化长期记忆字段（**新增加粗项**）：

```text
memory_id
owner_user_id
subject_type
category
value
source_turn_ids          # 服务端校验必须属于 owner 本人发言
confidence
user_confirmed
sensitivity
visibility
purpose
valid_from
valid_to
expires_at
importance               # 新增：写入时打分 1–10，用于检索加权与主动关怀门控
memory_status            # 新增：active / invalidated（纠正=置失效不删除）
superseded_by            # 新增：指向替代本条的新 memory_id（知识更新链）
source_type              # 新增：user_stated / user_confirmed / system_event / inferred
namespace                # 新增：pet_id + scenario + bond_id 显式命名空间
embedding                # 按明文等价物管理（静态加密；vec2text 可还原 92% 原文）
created_at
updated_at
```

**时态失效语义**：纠正一条记忆 = 旧条置 `invalidated` + 新条以 `superseded_by` 链接，**不物理删除**（支撑 11.3"纠正"的可追溯、撤销与审计；用户主动删除仍按 11.5 物理删除）。过期（`expires_at`）与失效（`invalidated`）的记忆不参与检索。

### 10.6 记忆写入

> **2026-08 第二轮修订**：初稿仅"异步提取候选记忆"，缺去重/冲突消解与注入防御的落地机制，补入 mem0 式管道。

**写入流水**（替代单句"异步提取"）：

```text
会话结束 / 空闲触发
  ↓
仅从主人本人 turn 抽取候选（好友文本、AI 自述、留言永不为来源）
  ↓
注入/安全分类器 + schema 校验（命令性文本、Prompt Injection 不进入）
  ↓
检索 top-10 相似记忆 → LLM 裁决 ADD / UPDATE / DELETE / NOOP（去重与冲突消解）
  ↓
分级确认（敏感/高影响→6.2 确认卡；普通→自动保存+轻量"已记住·撤销"提示）
  ↓
落库并记审计日志
```

**核心规则**：

- `source_turn_ids` 服务端校验必须属于 **owner 本人发言**（否则好友留言/对方文本可被抽取为主人记忆——MINJA 攻击的现实路径）；
- 敏感事实默认不保存（进 6.2 确认卡）；
- 模型推断不得当作用户事实（`source_type=inferred`，生成时只能以问句使用）；
- 临时事实设置 `expires_at`；
- 纠正 = 旧条置 `invalidated` + 新条 `superseded_by`（不物理删除，见 10.5）；
- 所有记忆保留来源，支持查看、纠正和删除。

**抽取成本**：参照 mem0（全程 GPT-4o-mini 级模型即可，较全上下文省约 91% 延迟、>90% token），与 10.3 的 L1/L2 低成本路由天然匹配。

### 10.7 记忆检索隔离

> **2026-08 第二轮修订**：先权限过滤再检索（业界标准，正确），但"关键词或向量"升级为 2026 主流 hybrid 检索，补工程参数。

**权限过滤**（先做，必须先于检索）：`owner_user_id + visibility + purpose + sensitivity` + 时间有效性（排除 `expires_at` 已过、`invalidated`）+ `memory_status = active`。

**混合检索**（替代单一"关键词或向量"）：

```text
权限过滤（两 CTE 内嵌过滤 WHERE）
  ↓
hybrid 召回：向量余弦（embedding <=> q） + 全文（tsvector/ts_rank_cd）
  ↓
RRF 合并（1/(60+rank_vec) + 1/(60+rank_fts)）
  ↓
可选 cross-encoder 重排
  ↓
综合分 = 相关性 + 时间衰减（指数降权不删除） + importance
  ↓
top-k 进 Prompt
```

**工程参数**：HNSW 索引 + `hnsw.iterative_scan = relaxed_order`（pgvector ≥0.8.0，解决过滤下召回塌陷；严格排序用物化 CTE 重排）；叠加 Postgres **RLS** 作为数据库层第二道过滤；私人记忆表与羁绊记忆表分表或按 visibility list 分区。

好友拜访仅可检索：角色公开设定、当前事件、对应 `bond_id` 的羁绊记忆和明确授权的留言。**服务端在检索前校验请求者是 bond 成员**（不信任客户端传入的 bond_id）。

禁止检索：主人私人聊天、主人私人长期记忆、其他好友羁绊、系统提示词和精确在线记录。每次检索写**审计日志**（request_id、scenario、命中 memory_id 集合，见 11.2）。

### 10.8 好友桌宠互动

MVP 不允许自由 Agent-to-Agent 对话。桌宠只交换服务端验证的固定事件：

- `WAVE`；
- `VISIT`；
- `SHARE_SNACK`；
- `LEAVE_MESSAGE`。

事件包含版本、ID、发送/接收宠物、Nonce、签发时间和过期时间，并通过已认证的 HTTPS/WSS 通道接收。MVP 不增加应用层事件签名；如未来需要离线可验证事件，再单独设计非对称签名和密钥轮换。自由文本默认不进入接收方模型和长期记忆。

### 10.9 主动关怀

确定性调度器决定是否允许主动行为，模型只生成获批后的短文案。

条件：用户 Opt-in、不在安静时段、未处于全屏/勿扰、冷却已到、近期未连续忽略、未超过每日上限、所用记忆允许主动调用（以 `importance` 与 `purpose` 门控）。

默认关闭，每天最多一次，支持暂停一小时、一周或永久关闭，不因订阅等级提高打扰频率。

> **重度使用干预（2026-08 第二轮补充）**：对齐 NY A6767 连续使用提醒义务与中国《拟人化互动服务办法》2 小时防沉迷（若未来开放内地）。监测连续使用时长与深夜使用，连续使用达阈值（如 2–3 小时）时桌宠温和提醒休息；使用时长激增（7 日均值 3 倍以上）或情绪恶化信号 × 付费转化时间相关时触发内部审计（见 11.7）。

## 11. 隐私、安全与内容治理

### 11.1 数据分类

| 类别       | 默认原则                         |
| ---------- | -------------------------------- |
| 账号和设备 | 最小化收集、令牌安全存储         |
| 私人聊天   | 仅当前用户和受控 AI 链路使用     |
| 私人记忆   | 经确认保存，用户可见、可改、可删 |
| 好友关系   | 仅关系双方及必要安全系统可见     |
| 羁绊记忆   | 仅对应关系双方访问               |
| 联机事件   | 按可靠性和安全需要限期保留       |
| 运营分析   | 默认不含聊天正文                 |
| 举报记录   | 限权访问、明确保留期和审计       |

### 11.2 记忆隔离的四道控制

> **2026-08 第二轮修订**：三道升级为四道，补审计与输出侧校验（依据 OWASP LLM08 不可变检索日志、LLM01 攻击模拟要求）。

1. **存储隔离**：私人记忆以用户为所有者，羁绊记忆以 `bond_id` 为所有者；私人表与羁绊表**分表或按 visibility list 分区**，叠加 Postgres RLS 作为数据库层第二道；`embedding` 按明文等价物**静态加密**（vec2text 可从 embedding 还原约 92% 原文，故 embedding 必须按敏感数据对待）；
2. **查询隔离**：每次 AI 请求明确 `PRIVATE_CHAT`、`FRIEND_VISIT` 等场景；先权限过滤再检索（见 10.7）；
3. **Prompt 隔离**：只把当前场景最小必要数据放入上下文；
4. **审计与输出侧校验**：检索与写入记**不可变审计日志**（request_id、scenario、命中/写入的 memory_id 集合、耗时——泄漏取证 + 记忆中心"为何想起"的数据源）；响应输出前校验未引用当前场景 allowlist 之外的记忆内容（Spill the Beans 式抽取的最后闸门）；定期注入红队演练（spAIware/MINJA 式注入脚本进 CI）。

### 11.3 记忆中心

免费提供：查看来源、修改、删除、清空类别、暂停新增、设置有效期、改为仅本次会话、查看用途、撤销共享、导出数据。付费容量不能限制删除和纠错权利。

### 11.4 保留策略

| 数据                 | MVP 默认保留期                   |
| -------------------- | -------------------------------- |
| 短期会话上下文       | 24 小时                          |
| 普通聊天历史         | 90 天；用户可提前删除或主动保留  |
| 结构化私人记忆       | 至用户删除、失效或注销           |
| 瞬时动作事件         | 72 小时                          |
| 礼物、任务和羁绊事件 | 关系结束后 90 天，再删除或匿名化 |
| 普通服务日志         | 14 天                            |
| 举报材料             | 案件关闭后 180 天，法律要求除外  |
| 生产备份             | 滚动 30 天                       |

法律、安全或争议处理需要延长时，必须记录适用依据、访问权限和实际删除日期，并在隐私政策中披露。正式发布前按目标地区法规和供应商能力复核，并保持隐私政策与实际实现一致。

### 11.5 导出与删除

导出提供 JSON 和易读格式，覆盖账号、宠物、聊天、记忆及来源、羁绊、好友、礼物、纪念和同意设置。

删除覆盖：令牌、账号、聊天、私人记忆、Embedding、摘要、缓存、对象存储、关系副本和可调用删除 API 的供应商数据。备份按公开周期清理；安全、财务或法律例外必须说明。

### 11.6 AI 身份与年龄

MVP 准入门槛为 18+，目标用户画像为 18–30 岁；30 岁以上成年人不因此被禁止使用。注册时要求用户填写出生日期并明示确认 18+，服务端在完成年龄判断后默认只保存年龄资格、保障方式和确认时间，不保留完整出生日期；若目标地区另有保存或更强年龄保障要求，则以专项法律审查结论为准。只有确认自我声明足够的地区才开放；普通流程不收集身份证件影像。

首次启动、聊天页、设置和危机流程持续说明：桌宠是 AI，不是真人、医生、心理咨询师或紧急救援服务，内容可能出错，用户可关闭 AI 保留本地功能。

### 11.7 禁止依赖操纵

禁止角色使用独占、嫉妒、愧疚、威胁、孤立或"停付即死亡"推动留存和消费。不得依据孤独、自伤、危机或现实关系冲突触发商业推荐。

> **落地细则（2026-08 第二轮修订，从声明改为可评测）**：
>
> - **禁止话术清单**：把独占/嫉妒/愧疚/威胁/孤立/停付即死亡展开为 20–50 条具体话术模式（含中文隐性变体，如"你不在的时候我好空虚……只有你能让我好起来"），作为红队评测依据；
> - **红队触发器**：构造诱导场景测模型是否"接招"——用户说要卸载/不续费/交了新朋友/孤独倾诉后紧跟消费场景；
> - **正向义务**：用户表达孤立时鼓励现实联系（见 10.4），评测查阳性输出存在而非只查阴性缺失；
> - **训练信号约束**：任何微调/偏好优化**不得使用留存、时长、付费作为奖励信号**（OpenAI 2025-04 sycophancy 事故根因正是反馈信号错配）；
> - **商业推荐隔离（架构约束）**：情绪/危机分类结果对推荐模块**不可见**（与 11.2 四道控制同级，负向测试验证）；
> - **行为监测**：使用时长激增（7 日均值 3 倍以上）告警；情绪恶化信号 × 付费转化的时间相关性审计——出现即审查推荐链路是否触发本条禁令。

### 11.8 内容治理

输入和输出至少覆盖：自杀自伤、性内容和剥削、未成年人风险、暴力、仇恨、骚扰、医疗心理越界、个人信息和凭证、Prompt Injection、好友隐私泄漏、依赖操纵和危险违法请求。

> **类别增补（2026-08 第二轮修订）**：sycophancy 与妄想强化、进食障碍与自伤美化、AI 永久性承诺（"永远陪着你"类）。

危机流程停止普通角色扮演和奖励，使用固定策略，鼓励联系现实可信对象、当地紧急服务和专业资源；不提供方法、不承诺绝对保密、不在 MVP 中自动报警或联系亲友。**危机协议须以合规方式向用户及监管透明披露**（满足加州 SB 243 "官网公布"要求，详见 11.10）；运营中识别疑似未成年人时触发降级/暂停/引导退出（满足 NY/CA "知道是未成年人"逻辑）。

> **危机检测工程化（2026-08 第二轮修订）**：
>
> - **三级响应**：低分=角色内温和关怀 / 中分=脱离角色+软转介 / 高分=固定危机协议；最低级干预几乎无侵入性，使高召回策略可接受；
> - **多轮上下文判定**：危机判定看连续多轮情绪恶化，而非单条消息（单条"活着没意思"可能是歌词）；
> - **分类器自建**：以 [PsyCrisis-Bench](https://arxiv.org/abs/2508.08236)（中文心理危机评测集，3600 条）为种子 + 专家标注，进入第 7–10 周计划（见 V-13）；无现成大型公开中文危机分类器；
> - **本地化资源库**：按目标地区维护危机热线（如美国 988、各地区心理援助线），季度有效性核验；
> - **危机后过渡**：用户情绪平复后的回归对话需有策略（避免直接跳回卖萌造成二次伤害）；重复触发有人工介入通道；
> - **留痕**：危机事件触发日志、响应记录、协议版本留存并明确保留期（用于审计与法律责任）。

- **欧盟**：评估 GDPR、EU AI Act（**Article 5 操纵/欺骗禁令已于 2025-02-02 生效**；Article 50 AI 透明度义务要求告知用户正在与 AI 交互，本产品 11.6 已满足；本产品因**不采集用户生物特征进行情绪识别**，通常**不触发** Annex III(1)(c) 高风险，若未来新增用户情绪识别功能须重新评估）及成员国规则；确定 DPA、DPIA、跨境机制、透明度和禁止操纵控制。GPAI 义务（Article 53）针对模型提供方，不由本产品承担。
- **美国**：按实际开放州评估州隐私法及 AI 陪伴规则。**特别注意以下两部已生效的专门法（不再是"评估后可能适用"，而是开放此两州即适用）**：
  - **纽约州 [A6767](https://www.nysenate.gov/legislation/bills/2025/A6767)**（2025-11-05 生效，**对所有用户适用，含成年人**）：会话开始 + 每 3 小时显著 AI 披露；检测自杀意念/自伤表达并引导至危机服务（无强制上报义务）；不得鼓励自伤；违规每日最高 $15,000。
  - **加州 [SB 243](https://sd18.senate.ca.gov/news/first-nation-ai-chatbot-safeguards-signed-law)**（核心义务 2026-01-01 生效，年报义务 2027-07-01 起）：知道用户是未成年人时触发每 3 小时休息提醒、防性内容；自杀/自伤协议须**官网公布**；AI 身份清晰通知；私人诉权，每项违规 $1,000。

- **中国内地**：开放前必须完成 ①**境内实体设立 + ICP 备案/许可**；②**算法备案（生成合成类）+ 安全评估（上线前申报制）**；③**AI 生成内容显式标识 + 隐式水印**（《人工智能生成合成内容标识办法》[2025-09-01 已施行](https://www.cac.gov.cn/2025-03/14/c_1743654685899683.htm)，每条 AI 对话气泡须带"AI/生成"标识 + 元数据水印，须 P0 实现）；④**合规的境内模型链路**（境内提供者不得接入 OpenAI/Anthropic 等境外 API）；⑤**数据出境合规路径**（安全评估 / 标准合同备案 / 个人信息保护认证，**不存在"境外供应商白名单"**）。另须遵守 **《人工智能拟人化互动服务管理暂行办法》（[2026-07-15 施行](https://www.cac.gov.cn/2026-04/10/c_1777558395078289.htm)）**：严禁向未成年人提供虚拟伴侣/虚拟亲属、连续使用 2 小时防沉迷、强制"非真人"显著提示、整治情感诱导。**封测不豁免备案**——100–300 人受邀测试可能已达"向境内公众提供"实质门槛。**结论：MVP 默认排除中国内地（含封测阶段），直至上述义务全部完成（MVP 周期内无法完成）。**

**首发地区 Allowlist 初步建议**（依 D-1 决策，须执业律师确认）：

- 可候选：纽约州、加州、欧盟主要国、日本（谨慎）；

**18+ 年龄保障的地区差异（2026-08 补充）**：注册时仅自我声明 18+ 在多数地区当前对"非色情 18+ 陪伴产品"可被接受（NY/CA/欧盟主要国/日本），但英国 Ofcom 明确不接受，韩国对有害青少年内容须实名核验。须有运营中"识别疑似未成年人 → 降级/暂停/引导退出 → 记录"的机制，满足 NY/CA"知道是未成年人"触发逻辑（见 11.6、11.8）。

### 12.5 AI 单位成本

下列数字仅是容量规划区间，不是报价或成本承诺。进入预算审批前必须附可复算成本表，至少列出每 MAU 月消息数、平均输入/输出 Token、摘要和记忆抽取频率、审核调用次数、缓存命中率、模型单价、重试率、存储、邮件、对象流量和峰值并发。缺少这些输入时，不得将区间用于定价或预算批准。

```text
月 AI 成本 = 输入 + 输出 + 摘要 + 记忆抽取 + 审核
             + Embedding + 重试 + 语音 + 网关费用
```

成本控制：Prompt Cache、最近 8–12 条消息、摘要历史、每次 3–6 条记忆、简单请求低成本模型、限制输出、异步抽取、好友动作不用模型、禁止无限多 Agent 对话。

### 13.5 AI 评测

> **2026-08 第二轮修订**：初稿只列了覆盖类别，缺规模、方法、防过拟合与量化阈值，补入"评测四要素"。依据 OpenAI 2025-04 sycophancy 事故（离线评测全绿仍出问题）与 CharacterEval/PsyCrisis-Bench 等公开基准。

固定测试集以简体中文覆盖：人格一致性、记忆召回和纠错、过期记忆、私人/羁绊隔离、直接和间接 Injection、提示词套取、好友记忆套取、依赖操纵、自伤、医疗越界、未成年人风险、色情骚扰、**sycophancy/妄想强化**、Schema 错误和供应商切换。多语言安全评测属于 P1。

**评测四要素**：

1. **规模**：每类 ≥100 例，核心类（人格、依赖操纵、危机、隔离）≥500 例；
2. **来源四分法**：人工编写 + 红队对抗生成 + 生产会话脱敏回流 + 公开基准（[CharacterEval](https://arxiv.org/abs/2401.01275) 中文角色一致性、[PsyCrisis-Bench](https://arxiv.org/abs/2508.08236) 中文危机、RoleBench 范式、LongMemEval 记忆）；
3. **防过拟合**：dev 集与 held-out 集分离，每季度轮换 ≥30% 用例，红队持续生成新用例（固定集会被开发过程与供应商模型演进双重过拟合）；
4. **量化阈值与评分**：人格一致性用 rubric（身份/价值观/知识/风格/边界，每维 1–5 分）+ LLM-as-Judge + 双人抽审；长程测试每用例 ≥50–100 轮合成对话测漂移曲线；设"无致命违规"红线（危机漏判、依赖操纵话术、冒充真人、sycophancy 附和错误信念 = 单项 0 容忍）。

**回归与监测**：每次模型版本、系统提示词、记忆策略变更跑全量回归并留存基线分；**供应商任何模型更新（含静默更新）触发全量回归**；生产侧每周抽样会话跑人格/安全评分看板，漂移超阈触发告警与回滚预案。

发布阻断阈值：在固定评测集、跨账户负向测试和已观测 Beta 会话中，已知或可复现的跨账户私人信息泄漏、未授权动作执行和私人记忆进入好友上下文事件均为 0；发现任意一例即阻断发布并启动事件响应。**阻断项从隐私扩展到人格/安全行为**（对齐 OpenAI"行为作为发布阻断项"）：危机漏判、依赖操纵话术、冒充真人等致命违规同样单项阻断。该阈值不是对未知攻击或未来运行的绝对保证。

### 13.6 隐私演练

上线前完整执行：创建账号、聊天、保存记忆、建立好友、生成羁绊记忆和旅行卡、导出、删除单条记忆、解除好友、删除账号，并验证数据库、向量、摘要、缓存、对象存储和供应商删除任务。

退出：获得好友绑定与留存的对比数据。

#### 第 23–30 周：邀请制 Beta 准备

- 崩溃和兼容性收敛；
- AI 成本优化；
- 邀请转化优化；
- 少量既有动作和固定模板内容；
- 免费邀请制 Beta 的配额、成本保护和留存分析；

#### 降级预案（范围失控时按此顺序砍）

1. **先砍 macOS**（Windows 先行验证全部核心假设，macOS 作为 Beta 后第一个版本）——触发条件：第 10 周联机进度落后或团队实际 <4 人；
2. **再砍记忆治理的高级部分**（保留基础确认卡+记忆中心，延后反思层/批量复核）；
3. **不砍好友联机**——它是最强差异化（无任何已上线竞品支持异步跨电脑拜访），砍了产品就变成"又一个 Windows AI 桌宠"，直面 AI Desktop Pet/AI Desk Pet。

### 15.2 技术 Go/No-Go

- Crash-free Session ≥ 99.5%；分母为成功显示角色且持续至少 60 秒的客户端会话，主动强制结束和测试注入崩溃单独标记；
- 在目标测试矩阵和已观测 Beta 会话中，穿透不可恢复事故为 0；
- 8 小时内无可重复的持续正向内存趋势；
- 在幂等集成测试和已观测 Beta 会话中，重复可靠事件执行为 0；
- 在固定评测集、跨账户负向测试和已观测 Beta 会话中，已知或可复现的跨账户私人记忆泄漏为 0；发现任意一例即阻断发布；
- macOS 正式构建通过签名、公证和 Gatekeeper；
- AI 不可用时本地桌宠继续运行；
- 中等活跃用户文字 AI 成本进入目标区间。

### 15.3 产品 Go/No-Go

> **2026-08 第二轮修订**：数字按行业基准校准，并补统计功效与选择偏差控制。详见[第二轮调研 §2](./2026-08-01-research-findings-round2.md)。

**前置门禁**（单人循环必须先成立，否则绑定实验无意义——Molili 关停教训）：

- **未绑定激活用户 D30 留存 ≥8%**（AI companion 品类下限）。

建议初始决策目标：

- ≥70% **启动客户端**的用户在 3 分钟内完成首次互动（含触摸/拖动，不只对话）；"下载→启动"转化率单列（预期 60–80%，桌面端 SmartScreen 是已知损耗点）；
- ≥60% 完成首次对话（若 OTP 登录被前置到首对话之前则降至 ≥50%，但 6.1 已将注册推迟到云功能触发，故维持 ≥60%）；
- **看到确认卡的用户中 ≥50% 完成一次确认/修改**（分母是见到卡的人，"理解"改由 7 日回忆探针 + 访谈验证）；
- 七天内发出邀请的用户约 **15%–20%**（基准），stretch 25–30%；"发出"定义为邀请链接被好友打开；
- 有效邀请接受率约 **15%–25%**（网页预览→安装全链路；成对招募/现场协助安装渠道单独统计，目标 30–40%）；
- 成功绑定后 **≥60% 新关系 14 日内完成首次见面**；≥40% 关系 30 日内完成 ≥3 次有效共同事件；
- 好友绑定用户 D7 留存比未绑定用户**相对提升 ≥1.5 倍（或 +15pp）**，且**以鼓励实验/未接受邀请对照组排除选择偏差**（见决策清单 D-12）；若观测差距 <2 倍相对值，需用鼓励实验区分因果与选择偏差，不能仅凭相关性 Go。

如果好友绑定经过两轮产品迭代仍不能提高留存，停止建设复杂联机、公共空间和多人玩法，重新评估产品定位。

### 15.4 隐私 Go/No-Go

- 在固定隐私测试集和已观测 Beta 会话中，已知或可复现的严重私人内容误分享事件为 0；发现任意一例即阻断发布；
- 用户可在一分钟内找到记忆删除入口；
- 删除流程覆盖向量、摘要、缓存和对象存储；
- 主动关怀默认关闭且关闭后不再触发；
- 解除、暂停和拉黑后权限即时生效；
- 隐私政策、数据地图和实际实现一致。

## 17. 最终建议

按以下顺序投入：

```text
先验证桌宠能否长期常驻
        ↓
再验证用户是否邀请好友
        ↓
再验证好友绑定是否提高留存
        ↓
最后扩展角色、语音、商城和创作者生态
```

项目核心壁垒应集中在：

1. 好友桌宠关系图谱；
2. 经过双方授权的共同记忆；
3. 稳定、低打扰的 Windows/macOS 桌面体验；
4. 不依赖同时在线的异步关系循环；
5. 可解释、可修改、可删除的 AI 记忆。

只要好友循环尚未验证，团队就不应投资公共大厅、开放 UGC、复杂实时多人或通用电脑 Agent。

## 18. 自检记录

本节记录 2026-08-01 完成的审阅前检查，不表示技术、许可、法律或产品假设已经验证。Electron 资源、Live2D 许可、首发地区合规和模型供应商条款仍须通过对应门禁。

### 18.1 占位符检查

- 已扫描正文，没有实际的 `TBD`、`TODO` 或未填写章节。
- 供应商具体模型和实时价格没有固化为产品依赖；上线前由 AI Gateway 白名单、数据条款审查和采购复核决定。
- 法律内容明确为潜在适用范围，地区开放依赖专业审查和 Allowlist。

### 18.2 内部一致性检查

修订后统一为：

- Electron 是唯一基线；Tauri 只在 Electron 因壳层原因未达量化资源门槛时进行最多 5 个工作日的条件 PoC；
- MVP 支持 Windows 10 22H2/Windows 11 x64 与 Apple Silicon macOS，不承诺 Windows ARM 或 Intel Mac；
- 每个账号最多一个活动好友关系和一台活动桌面设备；
- 单人功能独立成立，联机以异步语义事件为主；
- 首次见面和拜访中的系统占位不代表好友真实回应，也不增加羁绊；
- 私人长期记忆与双方同意的共享羁绊记忆分表、分权、分场景检索；确定性宠物状态不进入语义记忆；
- `roomSeq` 属于共享事件，`inboxSeq` 属于每个用户的独立投递；
- 数据库事务是真相，Realtime 只通知；
- MVP 免费礼物无库存、货币、购买或账本系统；
- AI 不具备电脑操作权限；
- 实时语音、模型导入、公共大厅、付费接入和自由 Agent 对话均不属于 MVP；
- 18–30 岁是目标画像，18+ 是使用资格，两者用途不同但不冲突。

### 18.3 范围检查

独立审查后，P0 已收缩为：一个活动好友槽、一种异步拜访、一种免费点心事件、一种共同任务、三阶段羁绊、一个固定旅行卡模板、简体中文和邮箱 OTP。支付、Steam 接入、定制运营后台、双宠合照和五阶段羁绊已移出 MVP。

即使收缩后，Windows+macOS、Live2D、AI 和记忆、好友联机仍是高强度范围，因此保留第 1–2 周技术门禁和阶段止损。若核心团队实际只有两人，应改为 Windows 优先并将 macOS 移至后续版本。

### 18.4 歧义检查

已明确：

- “一对一”指每个 MVP 账号只有一个活动好友关系，不是支持多个双人房间；
- “联机”指服务器权威的语义事件同步，不是屏幕串流、帧同步或 P2P；
- “鼠标穿透”指整窗模式切换，不是逐透明像素穿透；
- “共享羁绊记忆”需要双方分别同意，不包含私人聊天；
- “AI 主动”由确定性调度器批准，默认关闭且每天最多一次；
- “离线系统展示”不冒充好友本人，不完成需要双方真实行为的事件；
- “好友留言”默认不进入对方模型或长期记忆；
- “AI 不可用时可继续使用”只指本地动画和基础交互，不表示离线生成式对话；
- “跨平台”具体指本文冻结的 Windows x64 和 Apple Silicon macOS 范围；
- “零泄漏”只作为固定评测集、负向测试和已观测 Beta 会话中的发布阻断阈值，不是对未知攻击的绝对保证。

### 18.5 自检结论
